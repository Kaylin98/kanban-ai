# Backend

FastAPI app managed with uv (Python 3.14). It serves the API under `/api` and the static frontend build at `/`.

## Structure

- `app/main.py`: FastAPI app. `GET /api/health` returns `{"status": "ok"}`. Everything else is served from `STATIC_DIR` (default `../frontend/out`, the Next.js static export).
- `app/config.py`: reads the environment at import. `APP_USERNAME`, `APP_PASSWORD_HASH` (argon2) and `SESSION_SECRET` (32+ characters) are required, with no defaults: the process exits with a message if any is missing or invalid. `ENV` is `development` (default) or `production`; `PRODUCTION` turns on `Secure` cookies, removes `/docs`, `/redoc` and `/openapi.json`, and makes `client_ip` trust the last `X-Forwarded-For` entry (Render's proxy).
- `app/security.py`: `credentials_valid` (argon2 verify plus `hmac.compare_digest`; always verifies the password so timing doesn't reveal the username), `client_ip`, `RateLimiter` (in-memory sliding window, single instance), and `content_security_policy`, which hashes the inline `<script>` blocks in the static export so the CSP needs no `'unsafe-inline'` for scripts.
- Auth: `POST /api/login` checks the credentials and stores the username in a signed session cookie (Starlette `SessionMiddleware`: 7 days, `HttpOnly`, `SameSite=Lax`, `Secure` in production). 5 failed attempts per IP per 15 minutes, then 429. `POST /api/logout` clears it. `GET /api/me` returns `{"username"}` or 401. Use the `current_user` dependency to require a session on other routes.
- Every response gets the `SECURITY_HEADERS` (CSP, `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`) from a middleware in `main.py`. Unhandled errors return a bare 500; never put exception text in a response `detail`, log it instead.
- `app/board.py`: Pydantic models (`Card`, `Column`, `Board`) that mirror the frontend's `BoardData`. `Board` rejects boards whose columns aren't the fixed `COLUMN_IDS` or whose cards aren't each in exactly one column. `DEFAULT_BOARD` is the board every user starts with.
- `app/db.py`: SQLite via `sqlite3`, schema and approach in `docs/DATABASE.md`. File at `DATABASE_PATH` (default `../data/pm.db`, which is `/app/data/pm.db` on the Docker volume). `init_db` runs at startup: it creates the file and tables and seeds the `APP_USERNAME` row. `get_board` / `save_board` map between rows and `Board`, creating the default board on first use.
- Board API: `GET /api/board` returns the session user's board, `PUT /api/board` validates and saves a full board (422 if invalid). Both return 401 without a session.
- `app/ai.py`: OpenRouter calls through the `openai` SDK. `complete(messages)` returns the reply text; `parse(messages, schema)` returns it as a Pydantic model using Structured Outputs. The key comes from `OPENROUTER_API_KEY` and the model from `OPENROUTER_MODEL` (default `dots-studio/dots-3-note-preview:free`). OpenRouter falls back to `FALLBACK_MODELS` if it fails. Calls time out after 60 seconds, are capped at 4000 tokens (reasoning included), and ask for low reasoning effort.
- `app/chat.py`: the chat request and the AI's Structured Output (`AIResponse`: a `reply` plus a list of create / update / move / delete card operations, told apart by their `action` field, which must sort first; see the comment in the file), the system prompt (which includes the board JSON), `apply_operations`, which raises `ValueError` with a message written for the model for unknown card or column ids, and for a create whose title matches an existing card (case-insensitive; the model copying cards instead of moving them), and `correction_messages`, which ask the model to correct a rejected response.
- Chat API: `POST /api/chat` takes `{message, history}` and returns `{reply, board}`, where `board` is the saved board, or null if nothing changed. It logs the AI's operations on every attempt (INFO; `main.py` calls `logging.basicConfig` because uvicorn only configures its own loggers). If the operations are invalid, it logs the error and retries once with it. If the retry is also invalid, it leaves the board unchanged and returns 502. Any failed AI call (OpenRouter error, rate limit, timeout, a reply cut off at the token cap, or invalid JSON) also returns 502. Requires a session. 20 requests per user per hour, then 429. `ChatRequest` caps the message at 2000 characters and the history at 20 messages of up to 4000 (422 beyond). The chat history lives only in the frontend.
- `tests/`: pytest tests that use FastAPI's `TestClient`. `conftest.py` sets test credentials (`USERNAME` / `PASSWORD`, hashed at import) and points `STATIC_DIR` at `tests/static` so the tests don't need a frontend build. Its `client` fixture uses a fresh temporary database for each test, resets both rate limiters and runs startup; `logged_in` is the same client after logging in. Production mode and startup failures are tested in a subprocess (`run_app` in `test_main.py`), since `config` is read at import.

## Commands (run from `backend/`)

- `uv sync`: install dependencies
- `uv run uvicorn app.main:app --reload`: dev server on port 8000 (run `npm run build` in `frontend/` first, and set the required variables; `uv run --env-file` expands the `$` signs in an unquoted argon2 hash, so export `APP_PASSWORD_HASH` in single quotes in the shell instead)
- `uv run pytest`: run the tests (the live AI test is skipped without `OPENROUTER_API_KEY`; `uv run --env-file ../.env pytest` includes it)

## Docker

The root `Dockerfile` builds the frontend in a Node stage, then installs the locked Python dependencies with uv and copies the build to `/app/frontend/out`. It runs uvicorn on `$PORT` (default 8000). At startup, the `CMD` writes `/tmp/ca-bundle.pem` from the system CAs plus any `/app/certs/*.pem` mounted at runtime, and `SSL_CERT_FILE` points to it (for antivirus HTTPS scanning such as Norton; see `scripts/AGENTS.md`). `.dockerignore` keeps `.env*`, `certs/`, databases and `backend/tests` out of the image. The scripts in `scripts/` build and run it.
